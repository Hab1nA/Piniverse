# 10 · 与现有多 Agent 范式的对比

> 状态：草案 Draft v0.1 · 2026-08-29
> 上游：[00 愿景](00-vision.md) ｜ 下游：[11 实现路线](11-implementation.md)

把 Piniverse 放进多 Agent 编排的谱系里看清楚：它反对什么、吸收什么、与谁同路。各系统的描述基于截至本文撰写时的公开形态，细节以各自官方文档为准。

## 本章要点

- 核心对照轴是**权力的来源**：制度授予（身份）还是双边授予（契约）。
- Piniverse 与 Google A2A 在哲学上最同路（任务契约、对等体、生命周期），差别在于作用域：A2A 是跨组织的网络协议，Piniverse 是单机单工作区内、LLM 原生的会话组织方式。
- 诚实结论：小任务上，机构式子代理更便宜直接；Piniverse 的超额收益在网络变大、变深、需要审计时才显现。

---

## 1. 机构式子代理（Claude Code / ZCode 的 Task；Pi 官方 subagent 示例）

形态：主代理通过内置工具"生成"子代理，子代理以隔离子上下文执行单一任务，结果作为一条消息回流，随后即销毁。

| 维度 | 表现 |
|------|------|
| 权力来源 | 制度：spawn 行为本身授予父代理全部权威，子代理无拒绝权 |
| 深度 | 通常 1（子代理不能再委托）；框架固定 |
| 上下文 | 子代理从零开始，结果单管道回流——这是它最大的优点（上下文隔离）与最大缺点（父代理必须预先想清楚要什么） |
| 可观察性 | 父代理可见子代理的工具调用流；关系平凡（一条边）所以无需图 |

**Piniverse 吸收了什么**：隔离上下文的思想被吸收为"消息 + 工件指针"的信息流纪律（[07](07-context-information.md)）——对等体之间同样不共享转录。
**差异**：机构式子代理是"任务级函数调用"，Piniverse 是"组织级合同签订"。前者在 ≤1 跳的小任务上完胜（无协商开销）；一旦任务需要二层以上结构，父代理要么爆上下文，要么由人类手工接管编排——这正是 Piniverse 的协议指南也要警告的"该委托而不委托"。

## 2. OpenAI Agents SDK 的 Handoff

形态：对称的智能体之间**移交**整个对话与控制权，同一时刻只有一个活跃执行体，控制权沿链传递。

**同**：智能体对称、无固定层级——与对等哲学同源。
**异**：handoff 是**控制权转移**（我退出，你上台），而 Piniverse 的委托是**控制权分享**（我仍是 master，你执行，我保留 steer/取消/验收）；handoff 语义下单任务永远只有一条执行链，无法表达并行分工、多方汇聚（菱形）、或"我委托你同时我自己也在干活"。可以把 handoff 看作契约空间的一个退化点：accept 的瞬间 master 把自己的权利也全部让渡了。

## 3. 群聊式协作（AutoGen / CAMEL 等）

形态：多个智能体在共享对话流中轮流发言，由群聊管理器决定次序，或按角色扮演剧本协作。

**同**：没有制度层级，角色平等——表面上是最近的亲戚。
**异**：群聊的全部协调发生在**一条共享上下文**里，没有 per-task 的双边关系：没有"这个任务归谁、验收标准是什么、预算多少"的契约语义；消息是广播的（所有人对所有内容可见），上下文随参与者和轮次线性膨胀。Piniverse 的反命题恰恰在这里：协调不需要公共广场，**点对点信箱 + 任务契约**就能长出任意拓扑，且每个节点的上下文只包含与自己契约相关的消息。群聊适合头脑风暴式的共创；契约网络适合可分解的工程任务。

## 4. 编排框架的层级模式（CrewAI hierarchical、LangGraph 等）

形态：框架提供管理角色或图结构（节点+边+条件路由），开发者**静态声明**组织结构，运行时按图执行。

**同**：都认识到"层级/结构是有用的"。
**异**：结构是开发者预先设计的**制度**，不是运行中涌现的**过程**；图的改变=改代码/改配置，而 Piniverse 的关系图每毫秒都在由 accept/resign 自然改写。LangGraph 一类框架的价值在**确定性可复现**（图是版本化的代码）——这正是对等网络主动放弃的性质（[00 §5](00-vision.md#5-代价诚实清单)）：以可复现性换适应性。两者其实互补：确定性强的流水线子任务，指南会建议"别委托，写成普通脚本或直接自己做"。

## 5. Google A2A（Agent-to-Agent Protocol）

形态：跨组织的开放协议：Agent Card（能力发现）、Task 生命周期（submitted→working→completed…）、消息与 artifact 传递，认证与审计面向企业互操作。

**哲学上最同路**：对等体、任务契约、生命周期状态、工件传递、能力发现——几乎逐条对应 Piniverse 的 profile/契约/状态机/工件指针/发现（[01](01-concepts.md)）。可以说 Piniverse 是"A2A 思想在单机 Pi 会话上的本地化重演"。
**关键差异**：

| | A2A | Piniverse |
|---|-----|-----------|
| 作用域 | 跨组织、跨信任域、网络级 | 单机、单信任域、工作区级 |
| 传输 | HTTPS/JSON-RPC 等网络协议 | 本地文件信箱（一切皆文本） |
| 参与者 | 独立开发的远程 agent 服务 | 同构的 Pi 会话（同一 pv-ext） |
| 深度 | A2A 任务内的 agent 自己决定内部实现（通常不透明） | 委托链显式外露、全链可审计、预算逐层可推 |
| 信任 | 认证/授权是核心议题 | 单用户信任域，治理重心在失控防护 |

**吸收方向**：A2A 的 Agent Card 启发了 profile+capabilities 的设计；跨机演进（Q6）时，A2A 是现成的协议参照。

## 6. MCP（Model Context Protocol）——工具面，非组织面

MCP 解决"一个智能体接入外部工具/资源"，是**工具平面**的标准化；Piniverse 解决"智能体之间如何组织"，是**组织平面**的协议。两者正交：Piniverse 的对等体照常使用 MCP 工具。提及它是为了划界：Piniverse 不做工具集成，也不重复发明它。

## 7. 总对照表

| 维度 | 机构式子代理 | Handoff | 群聊 | 静态图编排 | A2A | **Piniverse** |
|------|------------|---------|------|-----------|-----|--------------|
| 权力来源 | spawn（制度） | 移交（制度） | 无（发言权均等） | 声明（制度） | 任务受理（双边） | **accept（双边）** |
| 层级深度 | 通常 1 | 链式无层 | 无层 | 图的深度（静态） | 不透明 | **动态、有护栏、无制度上限** |
| 双边同意 | ✗ | ✗（被动接管） | ✗ | ✗ | ✓ | **✓** |
| 并行分工 | 受限 | ✗ | 弱 | ✓ | ✓ | **✓** |
| 共享上下文 | 隔离 | 全量移交 | 全共享 | 按节点 | 按任务 | **按契约（消息+工件）** |
| 关系可审计 | 弱 | 弱 | 弱 | 图即代码 | 协议级 | **日志重放级** |
| 拓扑变化 | 无 | 无 | 无 | 改代码 | 实例级 | **运行时涌现** |
| 小任务成本 | 低 ✓ | 低 | 低 | 中 | 高 | **中（有协商开销）** |
| 深层任务成本 | 高（父过载） | 中 | 高（上下文爆） | 中 | 中 | **中低** |

## 8. 综合：层级作为制度 vs 层级作为涌现契约

谱系的深层分歧只有一个问题：**"上级对下级的权力，从哪里来？"**

- 制度派回答"从框架/代码来"：spawn 那一刻、图声明那一刻，权力就配置好了。好处是可预测、零协商成本；代价是组织结构无法比开发者的预判更聪明。
- 契约派（A2A、Piniverse）回答"从对方同意来"：权力是双边条款，随任务生灭。好处是组织可以比任何预判更深、更灵活、全程留痕；代价是每份关系都要付协商与簿记的成本。

Piniverse 的立场是务实的混合（[06 §2](06-network-dynamics.md#2-决策模型会话自己的选择)）：**小任务用不起契约，就别用**——直接自己做或用普通工具调用；只有当任务真的需要组织（并行、专长、深度）时，才让它长出网络。框架不预判组织何时值得存在，把判断留给每个会话——这本身就是"基础设施无决策"原则在时间维度上的延伸。

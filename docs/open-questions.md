# 开放问题与决策记录

> 状态：持续维护 · 2026-08-29
> 上游：全部设计文档

设计文档采用"推荐方案 + 备选 + 权衡"的写法，凡未收敛的判断集中登记于此。每条问题标注：**当前倾向**（若有）与**状态**（`Open` / `Leaning` / `Decided→ADR-xxxx`）。走向实现的每一次收敛，按文末 ADR 约定留下记录。

## A · 身份与生命周期

### Q1 · resume / fork 后的身份与契约归属
- **背景**：[05 §6](05-registry-lifecycle.md#6-恢复与异常) 默认"实例绑定身份"：resume 换新 PID，旧契约由 master 重新委托。代价是崩溃恢复后有一次重委托开销。
- **候选**：(a) 维持默认；(b) PID 固定于会话文件 + 回归 TTL（限时 reclaim 旧契约）。
- **当前倾向**：(a)。机制复用（发现/要约/handoff_notes）已覆盖场景，(b) 引入"身份回归"特例。
- **状态**：Leaning。M2 压测真实恢复频率后定。

### Q14 · 档案与状态卡的新鲜度
- **背景**：profile 是注册时自述的（[05 §4](05-registry-lifecycle.md#4-发现)），会随经验腐烂；状态卡内容取舍（[07 §4](07-context-information.md#4-进入-pi-上下文)）未定稿。
- **候选**：profile 定期自动刷新（如每 N 个完成的契约后重写）；状态卡增加"最近 3 条消息标题"。
- **当前倾向**：profile 在完成契约时刷新（事件驱动，不加 timer）；状态卡 M2 按实测上下文收益定。
- **状态**：Open。

### Q15 · 多操作员
- **背景**：当前单用户信任域假设（[08 §1](08-safety-governance.md#1-威胁模型)）。
- **候选**：`roles.operator` 扩展为多主体 + 权限分级。
- **当前倾向**：暂不做；记录需求来源再议。
- **状态**：Open（远期）。

## B · 协议

### Q3 · broadcast 的 `all` 模式
- **背景**：[03 §5](03-message-protocol.md#5-寻址与名字) 移除了"全体必达"，只有话题订阅。紧急全网通告（如"仓库即将迁移"）如何办？
- **候选**：(a) 永久移除，operator 需要时逐个发或经 hub 代发；(b) 保留 `topic:all` 但仅 operator 可用 + 强限流。
- **当前倾向**：(b)，作为 M4 的 policy 选项。
- **状态**：Leaning。

### Q8 · report 的合并与节奏参数化
- **背景**：[03 §7](03-message-protocol.md#7-与-pi-注入机制的对齐) 的注入合并是固定策略；[04 §4](04-control-relations.md#4-权利义务) 的汇报节奏是指南。
- **候选**：契约里允许 master 声明 `report_cadence`（覆盖指南默认）；合并策略按消息类型细化。
- **当前倾向**：M2 保持指南级；实测上下文曲线后决定是否协议化。
- **状态**：Open。

### Q10 · 消息签名 / 哈希链 / 应用层 ack
- **背景**：[03 §8](03-message-protocol.md#8-版本化) 与 [08 §5](08-safety-governance.md#5-审计日志)。单机信任域内防篡改价值有限。
- **当前倾向**：M4 可选项；`ack` 类型不引入（契约状态机即回执）。
- **状态**：Leaning（倾向最小化）。

### Q12 · 混版本共存
- **背景**：[03 §8](03-message-protocol.md#8-版本化) 的宽松向后读在混版本时可能丢字段。
- **当前倾向**：单工作区同步升级为主；hub 检测版本漂移并告警即可。
- **状态**：Open（低优先）。

## C · 网络动力学

### Q4 · 成环规则的精细化与多主仲裁
- **背景**：[06 §3](06-network-dynamics.md#3-等待与死锁) 硬性禁环（连 A⇄B 同时互持也禁）；[04 §7](04-control-relations.md#7-多主并行与冲突) 多主竞争靠指南。
- **候选**：(a) 维持硬禁；(b) 允许"非阻塞环"（双方契约均声明 fire-and-forget）并配运行时告警；(c) 协议级多主优先级队列。
- **当前倾向**：MVP (a)；(b)(c) 等 M2+ 实测。
- **状态**：Open。

### Q13 · 实现期技术问题集合
- **背景**：随 [11](11-implementation.md) 施工出现：Windows 文件锁的最终选型、policy 热更新的一致性窗口、深度/限流参数自适应、`spawn_peer` 的权限边界、pv-hub 技术栈、与 Pi 上游的协作点（如自定义消息渲染钩子）。
- **当前倾向**：逐项在实现 PR 中记录，收敛后立 ADR。
- **状态**：Open（随实现增长）。

## D · 治理

### Q5 · 争议仲裁
- **背景**：[04 §4](04-control-relations.md#4-权利义务) 中 master 恶意验收 / worker 恶意辞任 / steer 越界争执，当前都汇于 escalate 到人。
- **候选**：(a) 永远人工仲裁（现状）；(b) 引入第三方对等体评审契约（本身就是一份契约，递归一致）。
- **当前倾向**：(a) 为主，(b) 作为指南推荐的自救手段（不进协议）。
- **状态**：Open。

### Q6 · 跨工作区 / 跨机扩展
- **背景**：[07 §2](07-context-information.md#2-传指针不传全文) 的指针语义、[08 §7](08-safety-governance.md#7-与-pi-容器化的对接) 的沙箱凭证验证、[05](05-registry-lifecycle.md) 的注册表联邦，都假设单机。
- **候选**：共享挂载点（NAS/同步盘）；A2A 式网络传输；ssh 远端对等体。
- **当前倾向**：MVP 明确不支持；演进时优先评估 A2A 协议参照（[10 §5](10-comparison.md#5-google-a2aagent-to-agent-protocol)）。
- **状态**：Open（远期）。

### Q7 · 机械强制性的边界
- **背景**：三处纪律无法用钩子可靠强制——summary 如实性、"贴指针不贴全文"、限权契约与私活混做（[07 §2](07-context-information.md#2-传指针不传全文)、[08 §3](08-safety-governance.md#3-策略执行点)）。
- **候选**：启发式校验（body 大文本占比、路径行占比）给警告不给硬拦；混做场景引入"契约工作区子目录"约定。
- **当前倾向**：M3 做启发式警告；硬隔离交给容器化。
- **状态**：Open。

### Q11 · hub 何时必须存在
- **背景**：[02 §5](02-architecture.md#5-传输决策为什么文件信箱优先) 坚持 hub 旁路。当网络规模大到清扫/看板成为刚需时，hub 的最小职责需要冻结下来，防止它爬回消息路径。
- **当前倾向**：hub 的职责上限写死为"读一切、发 notify、执行 operator 工具"；任何进入消息路径的提案需 ADR。
- **状态**：Leaning。

## E · 词汇与展示

### Q1a · 角色命名
- **背景**：master/worker（[01 §2](01-concepts.md#24-任务契约本体系的中心概念)）是当前规范；是否需要更精确/中性的术语（delegator/performer、client/server）。
- **当前倾向**：维持 master/worker（中文：委托方/受托方）；文档中"主/从"仅作修辞。
- **状态**：Decided（ADR-0001 候选）。

### Q9 · reputation 的用途边界
- **背景**：[05 §1](05-registry-lifecycle.md#1-注册表的内容与形态) 只展示不排序。
- **候选**：(a) 永远只展示；(b) 参与 `query_peers` 排序。
- **当前倾向**：(a)。排序是决策，属于发起方 LLM；一旦基础设施参与排序就滑向撮合（P6 边界）。
- **状态**：Leaning（倾向 (a)）。

## ADR 约定（轻量）

走向实现后，凡"改变协议字段、状态机语义、policy 默认值、组件职责边界"的收敛，必须在 `docs/adr/NNNN-标题.md` 立档，格式：

```markdown
# ADR-NNNN · <标题>
- 状态：Proposed | Accepted | Superseded by ADR-MMMM
- 日期：YYYY-MM-DD
- 背景：<为什么现在要决策，关联 open-questions Qxx>
- 决策：<一句话结论>
- 理由：<备选与权衡，为何选它>
- 影响：<需要改动的文档章节与代码模块>
```

规则：一个 ADR 只记一个决策；被推翻不删除、标记 Superseded；本文档中对应问题的状态改为 `Decided→ADR-NNNN`。
